# CLAUDE.md

This project is **WRL Forge** (formerly `vrmlpad`). See `AGENTS.md` for the full mission (including the three-profile model: Mall Item, World Project, Generic VRML97), architecture, conventions, and known gotchas — it applies equally here. See `docs/WRL_FORGE_ROADMAP.md` for the phased build-out plan and which phase is currently active.

A couple of Claude-specific notes on top of that:

- This is a tool-building project, not an item-authoring one. Don't pull in `../new-items/CLAUDE.md` conventions about VRML content itself (forbidden nodes, placement, etc.) except insofar as the Mall Item `validator.js` needs to check for them — this repo's job is the tool, not the mall items. Those conventions are Mall Item-specific; do not assume they apply to World Project or Generic VRML97 code.
- Before adding any dependency (editor component, 3D lib, UI framework), re-read the "Mission" section in `AGENTS.md`. The Mall Item lane (Phase 2B1) **and** the World Project lane (Phase 4B) now have embedded X_ITE previews (`x_ite` MIT is a root dependency; see `docs/PREVIEW_ARCHITECTURE.md`), but that is **not** a license to add rendering dependencies opportunistically: X_ITE is the only approved renderer, and the Generic VRML97 embedded preview (Phase 5) still needs its own approved lane. Do not build a custom VRML/X3D renderer. Shared preview/fit modules live in `src/preview/` — reuse them, don't duplicate. The World preview is a **separate profile** (`renderer/world-preview.js`, `src/world-project/preview-source.js`): it reuses the shared gzip reader but applies **no** Mall fit/guide/placement/cap rules.
- Don't rename internal symbols (IPC channel names, the `window.vrmlpad` bridge, variable names) purely for branding consistency with the new product name. `AGENTS.md` explains which ones were intentionally kept during the rename and why. The World Project lane (Phase 4A) deliberately reuses the `window.vrmlpad` bridge (adding a `world` sub-object) rather than introducing a new bridge name.
- The **World Project** lane lives in `src/world-project/` (production, read-only resolver + Phase 4B `preview-source`), `renderer/world.html` + `world.js` + `world-preview.js` (its own workspace page, now with an embedded X_ITE preview), and confined `world:*` IPC in `main.js` (incl. `world:previewLoad` + the `wrlworld://` scheme handler). It is a **separate profile** from Mall Item — never apply `validator.js`/Mall rules to it, and never encode a fixed texture limit (the ~20 figure is disproven; worlds reach ~70). It is strictly read-only (no repair/copy/rename/delete/package/upload); the Phase 4B preview only reads and is **analysis + display only** (never marks a project upload-ready). The world preview authorizes X_ITE's nested reads from the asset graph via the `wrlworld://` scheme (confined to project root, gzip-decompressed) — do not let X_ITE reach `file://` or the network directly, and do not create `.edit.wrl` files to preview a world. `qa/world-recon/*` re-export the production modules; don't duplicate them. Any Electron visual work still routes through `VisualQaRunner` (`qa/phase-4b-world-preview/orchestrate.js` is the Phase 4B run). See `docs/WORLD_PROJECT_ARCHITECTURE.md` and `docs/PREVIEW_ARCHITECTURE.md`.
