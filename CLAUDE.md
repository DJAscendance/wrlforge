# CLAUDE.md

This project is **WRL Forge** (formerly `vrmlpad`). See `AGENTS.md` for the full mission (including the three-profile model: Mall Item, World Project, Generic VRML97), architecture, conventions, and known gotchas — it applies equally here. See `docs/WRL_FORGE_ROADMAP.md` for the phased build-out plan and which phase is currently active.

A couple of Claude-specific notes on top of that:

- This is a tool-building project, not an item-authoring one. Don't pull in `../new-items/CLAUDE.md` conventions about VRML content itself (forbidden nodes, placement, etc.) except insofar as the Mall Item `validator.js` needs to check for them — this repo's job is the tool, not the mall items. Those conventions are Mall Item-specific; do not assume they apply to World Project or Generic VRML97 code.
- Before adding any dependency (editor component, 3D lib, UI framework), re-read the "Mission" section in `AGENTS.md`. Root runtime deps are deliberately minimal: `x_ite` (MIT) is the only `dependency`; `electron` and `electron-builder` (MIT, Phase 6A Windows build tooling) are `devDependencies`. Do **not** add a third-party archive library — the World Project Bundle ZIP uses Node's built-in `zlib` (`src/world-project/zip-writer.js`). The **optional** external editor is discovered cross-platform via `src/editor/editor-locator.js` (Linux `codium`/`code`, Windows install-location search + `WRL_FORGE_EDITOR`/`settings.json` override, clear not-found message); don't reintroduce a hardcoded `codium` spawn. VSCodium is optional, not required. The **VRML97 parser** foundation is now **built** (Phase 7A): a dependency-free, token-driven tokenizer + structural parser under `src/vrml/` (`tokenizer`/`parser`/`ast`/`diagnostics`/`analyze`/`asset-refs`/`index`; see `docs/VRML_PARSER.md`). It is pure (text in, tree + diagnostics + semantic index + asset-refs out — no fs/Electron) and profile-neutral. It **is wired into the native editor** (Phase 7B) for highlighting, syntax diagnostics, advisories, and outline generation, but it has **not** replaced the `validator.js` Mall validator, World Project scanner, preview resolver, packaging logic, or URL extraction — do not route those through it without a new approved lane. 7A1 corpus-hardened it (hyphen/plus identifiers, multiline strings, header encoding case, lenient Cybertown/Blaxxun `ROUTE`/`PROTO`-in-MFNode-array; 98.1% corpus diagnostic reduction). Its **semantic scope is flat and NOT authoritative** (PROTO DEF leakage, cross-PROTO false duplicate-`DEF`, USE-before-DEF, context-insensitive `IS`) — a future scope-aware lane fixes that; do not surface those `DEF`/`USE`/`ROUTE` diagnostics as authoritative, and do not attempt the PROTO-scope rewrite here. Reuse it (`require('./src/vrml')`), don't fork it. The **native editor** on top of it is now **built** (Phase 7B, `docs/NATIVE_EDITOR_ARCHITECTURE.md`): a CodeMirror 6 workspace (`renderer/editor.html`/`editor.js`, `src/editor/*` incl. `wrl-document`/`file-io`/`language`/`session`/`session-store`/`path-authorizer`/`editor-controller`/`ui-state` + the bundle-only `browser/editor-view.js`), reachable from both lanes via `editor:*` IPC and the `window.vrmlpad.editor` bridge. CodeMirror (`@codemirror/*` + `@lezer/highlight`) and `esbuild` are **MIT devDependencies**; the bundle is `renderer/vendor/wrl-editor.bundle.js` (gitignored, regenerated by `npm run build:editor`), so runtime deps stay `x_ite`-only — **no CDN, no second grammar** (the `src/vrml` parser is the sole authority via `language.js`). Main owns every path (renderer sends text+intent+opaque sessionId, never a write path; Save As uses a main dialog; a World reference is authorized against the scan graph + realpath). Editor **guardrails still in force**: syntax diagnostics are authoritative but the flat-scope VRML040–044 remain **advisories only** and never block saving; do **not** route `validator.js`/World scanning/preview/packaging through the parser; the **unsaved-buffer X_ITE live preview is now built for BOTH profiles** — **Mall (7C2)** and **World (7C3)** — a split-view live preview of the in-memory editor buffer with **no temp file**; do **not** build a renderer (X_ITE only). (7C0 planning, the 7C4 Windows QA harness, 7C4.1 workspace guard, Feature A vision accommodations, **7C1** the buffer-overlay foundation, **7C2** the Mall live preview, and now **7C3** the World live preview have landed; **7C5** cross-platform acceptance has not.) The **7C1 foundation** is three dependency-free `src/preview/` modules (`buffer-overlay.js` — session-scoped, **byte-substitution-only**, never authorizes a path, requires an authorization proof from the Mall session / World scan graph; `preview-state.js` — last-valid-scene state machine; `preview-scheduler.js` — clock-injected 700 ms debounce). **7C2 wires them into the Mall editor** via `src/preview/mall-preview-bridge.js` (pure/injectable main-process authorizer — the renderer sends only `{sessionId, text, bufferVersion}`, never a path; it builds the `mallAuthorization` proof from the held Mall source only), `editor:previewLoad`/`previewSaved`/`previewAccept`/`previewClose` IPC, a split-view (`renderer/editor-preview.js` + `editor.html` `.preview-col` + divider, layout/split persisted) reusing `renderer/preview.js` verbatim (Original/Fit/guides/fit-report) via an injected source loader. **7C3 wires them into the World editor** via `src/preview/world-preview-bridge.js` (the pure/injectable World twin: authorizes the held doc against the **current scan graph** — root match, membership, exact-case, realpath re-check — and builds the `worldAuthorization` proof; the shared `editor:preview*` IPC routes by document context, plus `editor:previewRescan` = the explicit **Find new files** normal rescan — unsaved text NEVER expands authorization by itself): the unsaved **primary** is a string-swap with the primary's `wrlworld://` base; an unsaved **nested** WRL substitutes inside `resolveWorldRequest` through an injectable `overlayLookup` consulted only **after** root confinement + the allow-list (absent by default → the workspace disk preview is byte-identical); `renderer/world-preview.js` is reused verbatim via the same injected source, gaining opt-in `preserveView` (pure `src/preview/viewpoint-preserve.js`: DEF → unique description → index → first → default, + nav-mode restore) and `validateText` (nested buffers pre-parse through X_ITE so a broken nested edit keeps the last good FULL scene); `editor.html`'s CSP is the **World superset** (adds LOCAL `wrlworld:` — still **no new scheme**). Status copy is release-quality via `ui-state.js` `previewStatusModel` (Live/Updating…/Outdated/Showing last good version/Showing saved version/Some parts missing/New file reference found/too-large). Reuse these, don't fork them, don't route `validator.js`/World scanning/packaging through them, and keep `test/editor/script-load-order.test.js` in sync when adding editor-page scripts. **Vision accommodations (Feature A) are built** and renderer-only (no main/preload/IPC/CSP change): a persisted **zoom level** (`Ctrl`+`/-/0`) scales the code area via a **font compartment** in `editor-view.js` (decoupled from the theme compartment — five themes now, incl. **High Contrast**) *and* the chrome via a `--wrl-ui-scale` rem layer in `editor.html`; the pure zoom model lives in `ui-state.js` (`resolveZoom`/`zoomStep`/`zoomModel`). Reuse those, don't duplicate, and don't CSS-transform the (future) X_ITE canvas with the chrome scale. Reuse the pure `ui-state.js`/`file-io.js`/authorizer modules; don't duplicate. Visual QA runs only through `VisualQaRunner` (`qa/phase-7b-native-editor/`, `qa/phase-7c-vision/` for the zoom/theme states, `qa/phase-7c-mall-preview/` for the Mall live preview, and `qa/phase-7c-world-preview/` for the World live preview). On **Windows**, `qa/visual-qa/workspace-guard.js` (Phase 7C4.1) refuses UNC / network-drive / host-share workspaces (the WinBoat share) for QA/builds and is a **no-op on Linux** — don't route around it; see `docs/WINDOWS_NATIVE_QA_PLAN.md`. Direct upload/auth/networking **will not be built** (locked product decision); do not present its absence as a missing feature. Windows build instructions are in `docs/BUILD.md`; artifacts are labelled "Private Beta — Unsigned" (no signing/auto-update/store/public release). The Mall Item lane (Phase 2B1) **and** the World Project lane (Phase 4B) now have embedded X_ITE previews (`x_ite` MIT is a root dependency; see `docs/PREVIEW_ARCHITECTURE.md`), but that is **not** a license to add rendering dependencies opportunistically: X_ITE is the only approved renderer, and the Generic VRML97 embedded preview (Phase 5) still needs its own approved lane. Do not build a custom VRML/X3D renderer. Shared preview/fit modules live in `src/preview/` — reuse them, don't duplicate. The World preview is a **separate profile** (`renderer/world-preview.js`, `src/world-project/preview-source.js`): it reuses the shared gzip reader but applies **no** Mall fit/guide/placement/cap rules.
- Don't rename internal symbols (IPC channel names, the `window.vrmlpad` bridge, variable names) purely for branding consistency with the new product name. `AGENTS.md` explains which ones were intentionally kept during the rename and why. The World Project lane (Phase 4A) deliberately reuses the `window.vrmlpad` bridge (adding a `world` sub-object) rather than introducing a new bridge name.
- The **World Project** lane lives in `src/world-project/` (production, read-only resolver + Phase 4B `preview-source` + Phase 5A `package-plan`/`zip-writer`/`bundle-builder`), `renderer/world.html` + `world.js` + `world-preview.js` + `world-packaging.js` (its own workspace page, with an embedded X_ITE preview and a packaging section), and confined `world:*` IPC in `main.js` (incl. `world:previewLoad` + the `wrlworld://` scheme handler, and `world:packageAudit` + `world:buildReviewBundle`). It is a **separate profile** from Mall Item — never apply `validator.js`/Mall rules to it, and never encode a fixed texture limit (the ~20 figure is disproven; worlds reach ~70). It is read-only except the **one** explicit Build-World-Project-Bundle action (IPC channel `world:buildReviewBundle` — an internal name kept for stability, do not rename), which writes only a portable ZIP to a caller-chosen destination **outside** the project (never repair/copy/rename/delete/upload; never mutate the source). The Phase 4B preview only reads and is **analysis + display only**; the Phase 5A packaging is a **review + manual hand-off bundle** — labelled “WRL Forge World Project Bundle”, uploaded by hand through the Cybertown website, no direct upload (which will not be built), no server-certified-format claim (open questions in `docs/WORLD_PACKAGE_QUESTIONS.md`). The bundle uses a deterministic in-repo ZIP writer built on Node `zlib` only — **do not add a third-party archive dependency**. The world preview authorizes X_ITE's nested reads from the asset graph via the `wrlworld://` scheme (confined to project root, gzip-decompressed) — do not let X_ITE reach `file://` or the network directly, and do not create `.edit.wrl` files to preview a world. `qa/world-recon/*` re-export the production modules; don't duplicate them. Any Electron visual work still routes through `VisualQaRunner` (`qa/phase-4b-world-preview/` and `qa/phase-5a-world-packaging/` are the world runs). See `docs/WORLD_PROJECT_ARCHITECTURE.md` and `docs/PREVIEW_ARCHITECTURE.md`.
